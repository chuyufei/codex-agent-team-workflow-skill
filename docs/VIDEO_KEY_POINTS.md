# 视频文字关键点提炼

以下内容来自原始视频转写的机制提炼，不是逐字稿。

## 1. 长期对话就是 Agent

视频里的核心不是“开很多聊天窗口”，而是把一个长期 Codex 线程固定成某个职责的 Agent。比如：

- 产品规划 Agent；
- 产品开发 Agent；
- 选题 Agent；
- 内容创作 Agent；
- 素材准备 Agent；
- 数据复盘 Agent。

长期线程的价值在于积累上下文和形成稳定边界。

## 2. 分 Agent 不是为了角色扮演

视频里明确强调：大模型能力是通用的，不会因为你说“你很擅长写作”就真的变强。

分 Agent 的意义是：

- 把事情割裂开；
- 减少上下文污染；
- 支持并行和异步；
- 让验收更独立；
- 避免一个 Agent 既做球员又做裁判。

## 3. 要有 Agent 通讯录

每个 Agent 都要注册：

- 名称；
- 职责；
- 对应线程/对话 ID；
- 工作日志；
- workspace 或产出路径。

这样发消息时不用每次重新找 ID，可以直接按 Agent 名称投送。

## 4. 要有标准消息格式

视频里提到规划 Agent 给开发 Agent 发的是一套约定好的消息格式。这个格式不是临时聊天，而是协作协议。

标准消息至少应该包含：

- 任务 ID；
- from / to；
- 背景；
- 目标；
- 范围；
- 不做什么；
- 验收标准；
- 需要返回的证据；
- 下一步接收方。

## 5. 工作日志和产出要可追溯

每个 Agent 做了什么、产出了什么、为什么这么做，都应该写进日志。平时不一定要人工逐条看，但出现 bug 时可以追溯责任链。

## 6. 协作应该形成闭环

典型开发闭环：

```text
产品规划 Agent
-> 开发 Agent
-> 开发完成后通知规划/验收 Agent
-> 验收不通过则退回开发 Agent
-> 修复后再次验收
```

这比单向派活更可靠。

## 7. 可以做成异步流水线

自媒体例子里：

```text
选题 Agent
-> 内容创作 Agent
-> 素材准备 Agent
-> 人类拍摄
-> 数据复盘 Agent
-> 反哺内容方向
```

图片生成、数据复盘、内容大纲这类任务可以异步推进。

## 8. 不知道怎么拆时，先做三个

视频给出的最小方案：

```text
管理类 Agent：方向策略、需求、验收标准
执行类 Agent：具体生产、写代码、写内容
验收类 Agent：测试和检查
```

后续根据真实边界再增加专业 Agent。
